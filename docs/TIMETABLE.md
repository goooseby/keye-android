# 课表与直接阅读设计

范围：后续功能规划，尚未实现。本文定义目标交互和实施顺序；现有功能以 IMPLEMENTATION.md 为准。发布保持暂停。真实直播与增页链路已核对，尚未验证的状态转换仍保留验收要求。

## 产品路径

课程课件有两种同等重要的使用方式：按课程保存、批量获取并长期阅读；按日期和上课时间精准定位某一次课，直接打开。两条路径复用同一课次、同一本地课件和同一阅读进度，不建立第二套资料库。

推荐底部导航为“课表 / 课程 / 我的”，把课表作为完整的一级页面。课程保留最近阅读、全部课程和离线资料；批量获取从课表右上角进入专门的选择页面，保留日期范围、课程折叠和多选下载。下载管理作为任务过程入口，不单设第四个底部栏目。各页面保留自己的周次、日期、展开和选择状态，不互相覆盖查询结果。

## 学校状态的依据

官网课表前端直接调用 `/courseapi/v2/schedule/get-week-schedules`，与现有应用相同。课程对象的 `status` 驱动状态名称和样式，并非只根据开始、结束时间推算。已核对的官网定义如下：

| status | 官网含义 | 应用行为 |
| --- | --- | --- |
| 1 | 直播中 | 提供跟看，使用三条竖条的动态状态标识 |
| 2 | 未开始 | 显示课次与时段，不自动下载、不伪造直播状态 |
| 3 | 回放生成中 | 如已有课件可直接读；没有页面时说明课件尚不可用 |
| 5 | 无回放／暂无回放 | 不据此判定无 PPT，保留独立的课件查询能力 |
| 6 | 回放 | 点按阅读已有课件，或获取当前课件后阅读 |
| 缺失或其他值 | 未知 | 不默认归为直播，显示服务器可信文本或“状态未知” |

字段兼容数字和数字字符串。保留原始代码及可用的 status_label，避免未知状态被当作回放或直播。`is_live` 在官网还用于区分钉钉课程、在线教室等类型，不是正在直播的布尔开关。上课时间只用于排课和“当前时段”提示；不能把处于时段内的课程标成真实直播。

官网也根据发布／回看设置及角色处理可见性。接口状态不等于观看权限，课表应尊重当前账号实际可见范围，权限失败不能靠切换入口绕过。仍需核对 sub_review_type、sub_show 等字段的具体适用规则。

状态表示学校的视频／课程进度；本地课件状态另行表达“未保存”“已保存 X 页”“待补全”“正在获取”。“回放生成中”和“无回放”不意味着 PPT 一定不可读，界面不能把视频与课件可用性混成一个标签。

依据：[官网课表前端](https://video.jw.scut.edu.cn/static/js/3.7581509b70b2315450f1.js)中的 statusList、getStatusName 和 getTableList，以及[官网](https://video.jw.scut.edu.cn/)的中文语言资源。前端定义已与真实登录账号的课表数据交叉核对。11 月 4 日 09:51，“大数据营销”返回 status="1"、status_label="直播中"、is_live="1"，课表时段为 08:49:02–10:25:00。PPT 目录在 09:51:11 为 20 页，09:51:15 增为 21 页，最新页路径摘要随之变化；有效登录下可以同时识别直播和持续获取课件。

同周返回的五个回放课次均为 status="6"，另有一个未开始课次为 status="2"，其 status_label 为空；这说明状态文案须支持本地代码映射，不能只读 status_label。三种状态的 is_live 均为 "1"，再次确认该字段不能单独用于识别正在直播。

以上是当天实际观察，不代表已验证所有状态转换。直播结束到生成中、再到回放的过程，以及无回放和权限限制场景仍需按验收项目核对。研究记录只保留状态、时间、数量和摘要，不保存账号、Cookie、Token 或带鉴权的图片地址。

## 手机课表

默认采用“周日期条 + 当日时间轴”。顶部有上一周、日期范围、下一周和“今天”，点日期范围打开日历，可快速跳到上周二等任意日期。日期条显示周一到周日、日期、今天标记与有课提示；选中日期清楚突出。左右切周与上下浏览分开，避免阅读列表时误切日期。

下方按上课时间排列当天课程，显示开始／结束时间、课程名、教师和教室（接口提供时）、学校状态与本地保存状态。默认只保留少量时间留白，让上午、下午的课容易定位，避免把整天大量空白时间完整铺在手机上。标题可换行，操作触摸区至少 48 dp，不把每门课做成占据半屏的大卡片。

提供“周总览”切换，以七列时间格展示整周哪里有课。格内只保留课程简称和简洁状态，点按定位该课次；完整名称和操作在可读的详情中展示。周总览用于观察分布，当日视图负责精确操作。重叠课程须并列或显示数量并可展开，不能互相遮盖。无明确时段的课次放到“时间待确认”，不猜测其在时间轴的位置。

“上周二的机器学习”路径为：课表 → 上一周 → 周二 → 机器学习 → 阅读。看最近课件仍可直接走课程首页，不强制进入课表。

学校课程时间按学校时区解释和展示，日期查询、周界限与时段一致。课程的稳定标识继续使用账号、course_id 和 sub_id 的现有身份，不以“课程名 + 日期”合并同日多节课。

## 点开后的行为

| 课次状态 | 点按主行为 |
| --- | --- |
| 直播中且允许观看 | 直接进入课堂跟看，获取最新页面并等待新增 |
| 非直播、已有本地页 | 立即进入普通阅读器，恢复阅读位置；缺页可在就近入口补全 |
| 非直播、尚无本地页 | 进入“准备课件”的阅读状态并发起单课次获取，第一张可读页面保存后开始阅读 |
| 未开始、暂无页 | 展示明确课次信息，说明尚无课件，不自动创建无限等待任务 |
| 暂无页面或权限不足 | 就地解释原因，提供刷新或登录路径，不进入空白阅读器 |

单课次获取不强迫用户跳到下载管理；批量获取保持现有任务页流程。反复点同一课次复用已有任务，退出准备页或中途取消不删除已保存页；进程被结束后可重新进入并补缺页。阅读时页数增长不能自动打断回看，也不能因先下载到一张图就把整份课件视为永远下载完成。

不对一周所有课次逐个查询图片目录。展示课表只查询课表；课件目录在用户点开、主动补全或进入跟看时获取，避免把找课变成批量预下载。

## 直播快捷入口

课表内优先呈现当天实际直播课次：当前日期可自动定位到直播课程，历史周仍保持用户的定位，不擅自跳回今天。顶部提供“正在直播”入口，点按直接跟看；多门同时直播时紧凑列出可选课程，不武断选一门。

课程首页可在分段标签下方放一行紧凑的正在直播入口：三条竖条状态图标、课程名、时间和进入箭头。单门直接进入，多门显示数量并展开选择。只有登录有效、状态新鲜且平台确认直播时才出现；没有直播时不保留空卡片，不影响最近阅读。未登录不自动查课表，课表页提供正常登录入口。

三条竖条只表达平台确认的直播状态，不用随机音量数据伪装真实音频。提供“直播中”的可访问名称，关闭系统动画时静态显示，切到后台不继续播放装饰动画。

课表、首页入口和批量获取共用按账号和日期范围缓存的数据源，避免重复请求。前台显示这些界面时约每 60 秒更新直播状态，支持主动刷新；跟看中的 PPT 新页轮询仍约 3 秒，两者独立。后台、退出登录后停止请求；日期切换用请求代次拒绝旧结果回写。

网络失败保留缓存课表并显示更新时间，移除“正在直播”的确定性动效，不能将过期缓存继续当成当前直播证明；也不能因请求失败宣布课程已下课。学校明确返回结束状态后更新入口，不强行关闭正在阅读的跟看，保留页面与用户位置。

## 数据与实现边界

1. ScheduleEntry 增加可空的原始 status、status_label、教师、教室及必要的可见性字段，兼容旧 JSON。时间字段复用 startsAt／endsAt，课件的 remotePageCount 与已保存页面独立维护。
2. 增加小型状态解析规则及测试，未知代码保守处理；既有课表时段判断不再承担“确认直播”的职责。
3. 增加按账号和周缓存、更新时间、请求状态；与批量扫描状态分离，复用相同条目身份和认证处理。缓存不包含账号密码或明文请求凭据。
4. 首先实现周日期条、当日课程和单课次直接阅读，验证能找到历史课次、复用缓存并补缺页。
5. 再实现周总览、课表内直播入口与首页紧凑入口，统一动画和状态颜色。沿用现有合理目录，页面放在 ui、可复用小控件放在 ui/components，不预建多余模块。
6. 基于已确认的真实直播样本完成入口和课表，再验证直播结束转换、权限与状态更新延迟，决定 0.2.1 的最终发布范围。当前规划不包含音视频播放能力，也不因此引入服务器。

## 验收重点

- 官网同一课次的未开始、直播中、生成中、无回放、回放在应用中正确表达；未知字段和旧缓存不产生假直播。
- 上周二与本周二、同名课程、同日多课次不会混淆；周切换、今天、日历跳转及无课日有稳定状态。
- 已下载立即读，未下载按次获取，不重复建课件；部分页继续补齐，批注、书签、移除与阅读位置随页面保留。
- 视频回放尚未生成但 PPT 已可用时仍能阅读；没有课件、登录失效、无权限和断网分别说明。
- 当天与历史周、首页与课表之间跳转保持各自定位；多个直播入口和快速重复点击不会启动并行重复任务。
- 前台刷新、后台暂停、跨日、账号切换和过期响应不会泄露或串用另一账号的课表。
- 窄屏、大字号、深色和关闭动画时，课程名称、状态与触摸目标仍清楚可用。
